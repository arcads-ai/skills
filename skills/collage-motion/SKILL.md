# Arcads Collage Motion

One pipeline, two halves: **analyze** a reference into an editable spec, then **build** on-brand stills and assemble-from-empty motion. Everything runs on the Arcads MCP connector. The creator works in the halftone paper-collage / stop-motion-graphic editorial style: flat bold color field, halftone (printed-dot) elements, clean cut edges with a soft drop shadow between layers, one sharp idea per scene, and motion that builds the scene piece by piece instead of wobbling a finished frame.

Speak in the user's language. No em dashes anywhere in output; use periods or line breaks. Keep labels and copy free of emoji unless asked.

## Hard defaults (do not drift)

- **Image model:** `arcads_generate_image_nano_banana` with `model: "nano-banana-2"`. nano-banana-2 holds the paper-craft texture (dot pattern, cut edge, layer shadow, flat color) better than gpt-image, and takes up to 14 reference images.
- **Video model:** `arcads_generate_video_seedance_20` (max 15s per clip). Assembly is **prompt-driven**: pass the finished still as a reference and describe the build in words. Seedance 2.0 has no start/end frame, so it cannot interpolate empty to finished mechanically.
- **Frame-interpolation escape hatch:** when a clip genuinely needs a guaranteed empty-to-finished build, switch that clip to `arcads_generate_video_kling_30_pro` with `startFrame` = an empty-background still and `endFrame` = the finished still. Use this only for the clips that need it, never mix models within a single delivered set unless the user accepts the consistency cost.
- **Never call `arcads_add_text_overlay`.** Scene labels are burned in at image generation by nano-banana-2. If a label keeps degrading, reroll with `nbGenerations` or hand off labels to an external tool the user already runs (Figma, Canva); do not reach for the overlay tool.
- **Tools are deferred.** Load the exact Arcads tool schemas with `tool_search` before the first call each session (search "arcads image", "arcads seedance video", "arcads upload asset"). Confirm parameter names against what loads rather than assuming.

## The Arcads asset workflow (memorize)

Stills you want to reuse as video references must live in Arcads first. The canonical loop:

1. `arcads_get_upload_url` to get a presigned S3 URL.
2. `PUT` the local file bytes to that URL.
3. `arcads_register_image` to register it, which returns an asset id.
4. Reference it downstream as `videoassets/{id}.png`.

Local paths passed directly to generation tools are also auto-uploaded, but for an image generated by Arcads that you then animate, reuse its returned asset path directly. **Pass the product or brand reference image in every generation call** so subject and palette stay locked across the set.

## PHASE A: ANALYZE (decode a reference into an editable spec)

Run this whenever a reference is in play. If the user refers to an image but none is attached, ask for it rather than guessing.

### Mindset

The driving question is: "If I had to regenerate this exact frame from scratch on nano-banana-2, what would I need to specify?" Over-analyze on purpose, because the next request is almost always a variation ("same look, change the color field", "same style, different idea"), and that only works if every attribute is independently swappable. For every observation, name the technique and the why, not just a label. "Has texture" is nothing. "Visible halftone dot pattern on the black-and-white elements, dense at 45 lpi, which reads as printed-magazine craft instead of flat digital" is reproducible.

### Look in passes before writing

- The medium first: is this paper-cut, layered collage, halftone print, stop-motion frame, or a flat vector pretending to be paper. This decides everything downstream.
- The color field: the single flat background color, exact hex, evenness, any subtle paper grain on it.
- The elements: each cut-out piece, its outline crispness, the dot pattern inside it, its drop shadow (offset, softness, opacity) that lifts it off the field.
- The idea: the concept or visual pun the scene carries. This is the part worth protecting in any variation.
- The composition and depth layers: foreground pieces over midground over the flat field.
- Any burned-in label: content, font character, weight, placement, treatment.

### Output for each reference, in this exact structure

```
## [Short title describing the frame]

### Breakdown
A walk through the dimensions below under clear subheadings (Medium and craft, Color field, Elements and cut, Composition and depth, Idea, Label, Mood). Every element carries its technique and why.

### Generic prompt
One self-contained natural-language paragraph that names medium, color field, every element with its halftone and cut treatment, composition, label, and mood, ready to paste into nano-banana-2. No reference to "the image above".

### JSON spec
The field-by-field collage spec (schema below) as valid JSON.
```

### The collage JSON spec

This is the centerpiece. Valid JSON, no comments, no trailing commas, every field concrete. Each field is independently editable so a later "change only the color field" means rewriting one block and re-emitting the whole thing. **Always self-contained.** Never write "same as previous"; each generation has zero memory of any other.

`style_signature` is one compact liftable line (for example "flat cobalt field, halftone cut-outs, crisp edges with soft drop shadow, single editorial idea, premium print-craft") so the user can anchor other prompts to the look without carrying the whole object.

```json
{
  "medium": "",
  "craft_style": "",
  "aspect_ratio": "",
  "style_signature": "",
  "color_field": {
    "background_hex": "",
    "evenness": "",
    "paper_grain": ""
  },
  "elements": [
    {
      "what": "",
      "role": "",
      "halftone": "",
      "cut_edge": "",
      "drop_shadow": "",
      "color_treatment": "",
      "placement": ""
    }
  ],
  "palette_hex": [],
  "composition": {
    "layout": "",
    "depth_layers": "",
    "negative_space": "",
    "balance": ""
  },
  "idea": "",
  "label": {
    "present": "",
    "content": "",
    "font_character": "",
    "weight": "",
    "placement": "",
    "treatment": ""
  },
  "mood": "",
  "references_era": "",
  "negative_prompt": ""
}
```

`references/collage-dimensions.md` holds precise vocabulary for halftone, cut, layer, color-field, and label treatments, plus a fully worked example. Read it the first time you produce a spec so the specificity is calibrated.

### Multiple references

Decode each fully and separately. Then add one `## Shared style summary` capturing the common system: the color-field logic, the halftone density, the cut and shadow convention, the label treatment, and the idea-density. Make it specific enough to seed a fresh on-brand frame.

### Follow-ups

- "Replicate it": deliver the JSON spec as is, then go to Phase B to generate.
- "Make similar": keep structural fields (medium, craft_style, halftone, cut, color logic, composition) and vary surface ones (elements, idea, label) so it shares the look without copying.
- "Keep everything, change only X": rewrite only that block, re-emit the entire JSON.

## PHASE B: BUILD (stills then assemble-from-empty motion)

### B0: Pick the flow

If a reference was decoded in Phase A, the spec is your blueprint. If the user has only a brief or a product, draft the spec fields from the brief first (color field, idea, label), then proceed. If the user just wants stills and no motion, stop after B2.

### B1: Brief intake (one message, only if needed)

If the spec and the user's ask already answer these, skip and proceed. Otherwise ask all at once with `ask_user_input_v0`:

1. Assets to lock to? (upload a product photo or logo, or generate fresh)
2. Clip duration: 5s teaser, 10s standard, 15s full.
3. Format: 9:16 vertical, 1:1 square, 16:9 horizontal. (Seedance 2.0 supports 16:9 and 9:16; for 1:1 deliver square stills and animate on Kling.)
4. How many scenes in the set?
5. The idea per scene, or "you propose them".

### B2: Generate the stills

For each scene, call `arcads_generate_image_nano_banana` once with `model: "nano-banana-2"`, the spec turned into a prompt, the locked product/brand image in `referenceImages`, and the chosen `aspectRatio`. Burn the 2 to 4 word scene label into the prompt; do not plan to overlay it later.

Two stills matter per animated scene:

- **The finished still:** the full composition with all elements in place. This is the Seedance reference and the visual target.
- **The empty-field still (only if animating that scene on Kling):** the identical frame with the bare color field and no elements, used as `startFrame`. Generate it from the same spec with the elements removed so the field, grain, and label-less background match exactly.

Display each still. Ask "does this work or change it?" Reroll with an adjusted prompt or `nbGenerations` until approved. Keep one model across the set.

### B3: Assemble-from-empty motion

The signature is that the frame builds itself: it opens on the empty color field and the cut-out elements slide in from the edges and snap into place. Two routes.

**Default route, Seedance 2.0 (prompt-driven):**

Call `arcads_generate_video_seedance_20` with the finished still in `referenceImages`, the duration and aspect ratio from B1, and a prompt that explicitly describes the build. Seedance infers the assembly from the words plus the target frame.

Prompt shape:
```
Paper-collage stop-motion assembly. Open on an empty flat [color] field, no elements. One by one the cut-out halftone pieces slide in from the frame edges and snap into place with a crisp stop-motion cadence, soft drop shadows settling under each piece as it lands, until the full composition is assembled: [list the elements and final layout]. Burned-in label "[label]" appears last. Flat even lighting, premium print-craft texture, slight paper grain, no camera wobble, no zoom drift. [duration]s, [aspect ratio].
```

**Guaranteed route, Kling 3.0 Pro (frame interpolation):**

When the build must be exact, call `arcads_generate_video_kling_30_pro` with `startFrame` = the empty-field still from B2, `endFrame` = the finished still, and a prompt describing the element-by-element slide-in between them. This mechanically forces empty to finished. Use per-clip; do not silently mix Seedance and Kling across a set the user expects to look uniform.

Display the result. Offer: keep it, re-edit (same still, adjusted prompt), or render a variant (`nbGenerations` if supported).

### B4: Scale

Lock the look once (color field, halftone and cut convention, label treatment), then vary only the idea per scene. Batch the set the same way. Consistency across scenes is what makes it read as a brand rather than one-offs.

## Notes and rules

- **One model per delivered set.** Mixing nano/gpt for stills or Seedance/Kling for clips breaks the paper-texture and color consistency that makes the set look intentional.
- **Self-contained prompts always.** Every image and video prompt stands alone; generators have no memory of earlier calls.
- **Reference image in every call.** Keeps subject, palette, and craft locked.
- **Labels are burned in at generation,** never via `arcads_add_text_overlay`.
- **Confirm tool names and params with `tool_search`** each session; Arcads tool and model IDs change.
- **No em dashes, minimal emoji** in any drafted copy or label.
- **On failure:** explain briefly, reroll with adjusted params, or offer the Kling route for a stubborn assembly.
